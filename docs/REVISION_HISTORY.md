## REV-20260910-004：OPT-02 执行结果与失败传递

- 日期：2026-09-10。状态：已完成本地验证，未提交。
- 原因：修复 V-02、V-03，防止下单失败被吞掉或完成 Future 错误返回成功。
- 修改：新增 `execution.py` 的批次结果模型；`trades.py` 抛出提交结果未知异常并停止后续队列；`portfolio_manager.py` 根据真实订单状态记录 success / working / partial_failure / failed / unknown，完成 Future 与 CLI 接收原始失败。
- 生命周期：完成 Future 已结束时不覆盖它；原始异常不被收尾日志失败掩盖；直接连接模式在 finally 断开连接。
- 行为影响：Submitted / PreSubmitted 可以以 working 结束；PendingSubmit / PendingCancel 不能当作已确认成功；单笔部分成交后撤销记录为 partial_failure，拒绝或撤销不再伪装为成功。真实工作挂单仍可能在程序结束后存在。
- 验证：新增执行结果测试；最终全量验证 374 passed；覆盖率采样 77%，复跑边界见[联合验证记录](verification/OPT-02-05.md)。
- 回退：需同时回退批次模型、Trades 异常、管理器 Future 与 CLI 处理；回退会恢复原来的失败结果风险。

- 修改：入队时在原策略 orderRef 前缀后追加唯一后缀；首次提交或改价前先落盘。相同引用不能被再次作为新单提交；改价沿用原订单身份。
- 修改：开始规划前读取挂单、完成订单和成交；启动撤单等待最终确认；对重复成交、更正记录、其他账户及组合分腿分别处理。结果不明或旧工作挂单未解决时阻止新提交。
- 修改：运行期间断线使完成 Future 失败并终止执行任务，重连不会重启策略；退出释放账户锁。
- 配置影响：新增可选 `runtime.execution.state_directory`，默认 `~/.local/state/thetagang`，不依赖 SQLite 是否启用。状态目录应长期保留，同账户本机实例须共用；锁不协调其他主机或人工交易。
- 验证：覆盖独立进程争锁、磁盘失败、提交后断线、未知结果重启、部分成交/更正、组合对账、撤单未确认、异步订单确认及连接事件；详见[联合验证记录](verification/OPT-02-05.md)。Windows 分支本次未运行。

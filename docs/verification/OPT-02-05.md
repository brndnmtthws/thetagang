## 按事项验证

### OPT-02：执行结果与异常传递

`tests/test_execution_results.py` 覆盖空批次、全部成交、正常挂单、部分拒单、全部撤销、单笔部分成交后撤销、提交状态未知；提交异常和账户读取异常传递到完成 Future；已有 Future 异常不被覆盖；收尾日志失败不掩盖原始异常。

`Trades` 不再吞掉下单异常。券商调用结果不明时停止剩余队列，并使用 unknown 结果；成交/提交成功及部分成交订单数量保留在结果中。仅正常工作中的挂单允许以 working 结束，不能解释为全部成交。

### OPT-03：调价循环与审计关联

验证第一笔不适合调价时，第二笔仍得到处理；替换订单保留账户、订单号、完整 orderRef、有效期、算法、其他路由字段和原 intent_id；模拟模式不进入调价；调价前风险检查失败时不修改订单。

### OPT-04：运行互斥、去重与恢复

`tests/test_execution_state.py` 和 `tests/test_thetagang_startup.py` 使用临时文件、独立子进程及模拟 IB 事件验证：

- 同一账户的第二个进程不能获得锁，异常退出后可以重新获得锁。
- 提交前日志已经落盘；磁盘写入失败时券商接口调用次数为零。
- 提交后连接错误留下可恢复记录，重新加载日志也不能盲目重发。
- Submitted、PendingSubmit、PendingCancel、Inactive 或无历史证据均不能解除恢复阻断。
- 已确认成交/撤销可以结束恢复；部分成交、重复回调、其他账户成交、成交更正不会被重复累计。
- 组合订单的分腿成交不会直接相加，误判为整个组合已经成交。
- 改价必须关联原已确认订单；异步到达的确认状态可以用于随后改价。
- 重复连接事件只执行一轮 manage；运行期间断线会取消执行任务，Future 失败，释放账户锁，不因重连重新规划。
- 启动撤单未得到最终确认时停止规划。
- 模拟模式即使绕过正常分支直接要求提交，也不会创建虚假的待提交恢复记录。

互斥依赖所有本机实例共用状态目录，不是跨主机分布式锁。Windows 锁分支没有在本次 macOS 环境运行。恢复日志保留历史引用；损坏、权限错误或超过券商可查询历史范围时需要人工核实，程序不会自行清空记录。

### OPT-05：预计组合与整批资金预留

`tests/test_batch_risk.py` 验证：

- 两笔分别满足限额的买单，合计超限时整批拒绝，真实下单次数为零。
- 现有部分成交挂单只按剩余数量计入；其他账户和终态订单不占用本账户额度。
- 相同合约的重复/反向订单、展期组合与单独平仓触及同一分腿时拒绝。
- 计划卖出收入不增加可用资金；计划买入股票不能当成已有股票卖出或用于认购期权覆盖。
- 卖出股票不能破坏现有卖出 Call 的覆盖；已合格且乘数一致的组合展期可以保留原有覆盖关系。
- 股票、期权乘数、组合贷记/借记符号、未合格分腿和混合乘数检查。
- 非法数量、非有限价格、缺少风险账户值、币种不匹配和未确认挂单状态均阻断提交。
- 预计持仓反映队列变化，实际持仓对象不被修改；新增预计仓位不能被随后的管理阶段当作已成交仓位再次展期。
- 多策略订单及既有挂单合计保证金预留超限时拒绝；有效批次的所有预估均在第一笔真实提交之前完成。
- 预估的保证金释放不抵扣另一笔未成交订单的资金占用；预估超时阻断提交；模拟模式不发送 what-if 请求。

该检查采取保守的整批拒绝方式，不自动拆单、缩单或卖出融资。尚不支持自动币种换算、混合乘数组合或缺少必要资料的其他合约类型。存量挂单可能被重复保守计提；券商保证金预估不是成交保证，也不能锁定其他客户端的操作或市场价格。

## 配置、兼容性与恢复

`runtime.execution` 新增三个可选字段，缺省配置继续有效：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| state_directory | `~/.local/state/thetagang` | 同一账户所有本机实例必须共用的持久化目录；容器重启时应保留 |
| funds_buffer | 100.0 | 扣除后才可用于新订单的账户基础币种资金缓冲 |
| order_fee_buffer | 5.0 | 每笔订单最低费用预留；券商费用预估更高时取较高值 |

SQLite 关闭也会启用独立的执行恢复日志；模拟运行不改变日志中的交易状态。新入队订单在原策略前缀后追加唯一后缀，完整引用在改价中保持不变。以 `tg:regime-rebalance` 前缀查询历史的冷却期逻辑继续兼容。

`cancel_orders=false` 时，旧恢复日志中的工作挂单会阻止新提交；`cancel_orders=true` 时，仍只取消 OPT-01 限定范围内的订单，且必须确认取消完成。旧的无标识订单继续保留并纳入当前账户的风险检查。

回退代码前先确认当前账户没有尚未解决的提交，保留状态目录及数据库备份。恢复到不识别该日志的旧版本会失去这部分防重复保护。没有提供自动删除日志或强制重发的恢复捷径。
